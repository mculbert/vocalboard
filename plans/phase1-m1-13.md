# Phase 1 · M1 — Step 13: G1 round-trip fixture + final pass (action plan)

Detailed implementation plan for **Step 13** of [phase1-m1.md](phase1-m1.md). Written to
be implemented without the planning session's context. Read the Step 13 summary in
[phase1-m1.md § Step 13](phase1-m1.md#step-13--g1-round-trip-fixture--final-pass) and the
G1 convention in [conventions.md § G1](../design/conventions.md#g-data--persistence-integrity)
first.

## Goal

Two deliverables:

1. **G1 fixture round-trip.** Commit a real, v1-format `.vocalboard` SQLite file under
   `core/tests/fixtures/`, plus a committed *generator* and a *round-trip test* that opens
   the committed file and verifies it decodes to known state. Per
   [conventions.md § G1](../design/conventions.md#g-data--persistence-integrity): a persisted-format
   change must ship a migration **and** a fixture round-trip test that loads a
   previous-format file. M1 introduced four on-disk formats (the SQLite schema, the blob
   format-tag byte, the postcard snapshot/turn/label/metadata encodings, and the journal
   row layout); Step 13 closes the loop with a committed binary fixture that exercises them
   together. The fixture **must contain a real `Kind::Metadata` blob** (a `type = -1`
   journal row pointing at a stored metadata blob) so that opening it runs
   `load_metadata` + `load_current_metadata` against committed bytes — completing the G1
   round-trip for the metadata wire format on top of Step 9's *pinned-bytes* unit tests
   (this is the Step 9 downstream item flagged in
   [phase1-m1-09.md](phase1-m1-09.md)).

2. **Final pass.** Run the full M1 gate, confirm the [M1 exit criteria](phase1-m1.md#m1-exit-criteria),
   and reconcile any doc drift so [data-model.md](../design/data-model.md) stays authoritative.

**No new production code** beyond test-only helpers. This step adds tests, a committed
binary fixture, and a regeneration helper; it must not change any wire format or public
API.

## Background: what already exists

- `ProjectState::open_project(path, settings) -> Result<(ProjectState, OpenOutcome), EngineError>`
  is the public open path (`core/src/project/engine.rs`). `OpenOutcome { missing_tracks:
  Vec<u32>, recovery: Option<RecoveryInfo> }`. `ProjectState::sample_rate()` is public.
  **The trees and metadata are *not* exposed publicly** — `ps.current` is a private field
  of type `Arc<TimelineState>` with `trees: PerTrackTrees` and `metadata: Metadata`.
- The Tauri/`proto` boundary (`OpenProjectResult`) carries only `missing_tracks` +
  `recovery` — **no metadata content**. So the only *public* signal that metadata loaded
  is `missing_tracks` (derived from `metadata.tracks` via source-file resolution).
- Internal building blocks the generator will call (all `pub(crate)` or `pub`, reachable
  from an **inline `#[cfg(test)]` module inside the crate** — *not* from a `tests/`
  integration crate or a `bin`):
  - `db::Db::{create, conn, conn_mut}` (`core/src/db/mod.rs`).
  - `db::project::insert_project_row(&Connection, sample_rate)` (`core/src/db/project.rs`).
  - `db::store::put(&Connection, &Hash, &[u8]) -> Result<bool, StoreError>`.
  - `db::journal::{append_snapshot, append_delta_batch, append_metadata}(&Connection,
    CommandId, &Hash|&[u8], applied_at) -> Result<i64, JournalError>`.
  - `project::turn::store_turn(&Turn) -> (Hash, Vec<u8>)`, `project::label::store_label`.
  - `project::snapshot::{Snapshot, store_snapshot, snapshot_from_trees}`.
  - `project::delta::{Delta, Location, encode_delta_batch}`.
  - `project::metadata::{Metadata, ProjectMeta, TrackMeta, SpeakerMeta, ModelUse,
    SourceType, store_metadata}`.
  - `project::tree::ImplicitTimelineTree::from_sorted_elements(Vec<(Hash, Arc<T>)>)`;
    `ElementRef { start_sample, hash, element: &Arc<T> }` from `tree.iter()`.
  - `project::snapshot::{PerTrackTrees, TrackTree::{Labels, Speech}}`.
  - `project::command_id::CommandId::Unknown`.
- Precedent for a committed format fixture + round-trip test: `settings_v1.json` +
  `core/tests/tests/settings_roundtrip.rs`. Precedent for an `#[ignore]`d regeneration
  helper that prints/writes pinned artifacts: `metadata.rs::capture_pinned_values`.

## Key design decisions (lock these first)

### D1 — The fixture is one committed binary file, generated once

`core/tests/fixtures/project_v1.vocalboard` is a real SQLite database, committed to git as
a binary blob. It is generated **once** by the helper in D2 and then frozen; it is *not*
regenerated by `cargo test`. Regeneration happens only when the v1 wire format is
deliberately revised (a pre-1.0 allowance noted in the `mod v1` doc-comments), at which
point the operator re-runs the generator and bumps `min_app_version` per
[conventions.md § G2](../design/conventions.md#g-data--persistence-integrity).

The fixture must be a **single self-contained file** — no `-wal` / `-shm` sidecars. SQLite
opens in WAL mode (forced by `db::open_conn`), so the generator must checkpoint and switch
the file out of WAL before closing (see D2). Confirm only `project_v1.vocalboard` is staged.

### D2 — Regeneration helper: an `#[ignore]`d inline test

Add the generator as an `#[ignore]`d `#[test] fn gen_fixture()` in a **new inline
`#[cfg(test)]` submodule of `core/src/project/engine.rs`** (it needs crate-internal access
to `db::journal`, `db::store`, `store_metadata`, etc., which a `bin` or `tests/` crate
cannot reach). It is never run by the normal suite (it carries `#[ignore]` and would
otherwise overwrite the committed fixture). The operator regenerates with:

```
cargo test -p core --lib -- --ignored gen_fixture --nocapture
```

It writes to `concat!(env!("CARGO_MANIFEST_DIR"), "/tests/fixtures/project_v1.vocalboard")`,
removing any prior file first.

> **Why an `#[ignore]`d test and not a feature-gated `bin` (the 12a `gen_bindings`
> pattern)?** A `bin` is a separate crate and can only see `pub` items; the generator
> needs `pub(crate)` journal/store/metadata APIs. Mirroring `capture_pinned_values`
> (also `#[ignore]`d, also writes a regeneration artifact) keeps the access in-crate and
> the precedent consistent.

### D3 — The round-trip test asserts deep state inline

The authoritative round-trip test is also **inline in `engine.rs`'s `#[cfg(test)]`
module**, because verifying the *metadata* and *tree* contents end-to-end requires reading
the private `ps.current.{trees, metadata}` (exactly as the existing
`lifecycle_round_trip_with_content` test does). The public `OpenOutcome` exposes only
`missing_tracks` + `recovery`, which is insufficient to prove the metadata struct decoded
correctly.

The test must **not mutate the committed fixture**: it `include_bytes!`-loads the fixture,
writes the bytes to a `tempfile::tempdir()` copy, and calls `open_project` on the temp
copy. This also prevents `-wal`/`-shm` litter in the source tree and is safe even though
`open_project` opens read-write.

Additionally add a **thin public-API smoke test** in `core/tests/fixture_roundtrip.rs`
(parallel to `settings_roundtrip.rs`, satisfying the "fixtures-based round-trip suite"
location named by G1). It drives only the public API and asserts the publicly observable
surface: `open_project` succeeds, `sample_rate()` matches, `recovery.is_none()`, and
`missing_tracks` equals the fixture's missing file-track id (which *also* proves the
metadata blob was read — an empty/default metadata would yield an empty `missing_tracks`).
It uses the same copy-to-temp approach.

### D4 — Generator and tests share one content definition

To guarantee the test's expectations match what the generator wrote, define a single
crate-internal helper `fn fixture_spec() -> FixtureSpec` (in the engine test module) that
returns the sample rate, the per-track elements, the post-snapshot delta, and the
`Metadata`. Both `gen_fixture` and the inline round-trip test call it. This makes the
round-trip test a true G1 tripwire: if a wire format changes incompatibly, the committed
file's blobs either fail to decode (→ `EngineError`) or decode to structs that differ from
`fixture_spec()` (→ assertion failure).

## Fixture content specification

Deterministic, canonical-order content that exercises the snapshot, delta, and metadata
formats together. All `applied_at` values are fixed constants (no wall clock), all ids and
durations fixed. Sample rate **48000**.

**Timeline (snapshot at row 1, then one delta at row 2):**

- Track 0 (labels): one `Label { id: 1, text: "Intro", kind: Plain, post_label_silence:
  24000 }` → hash `hL`.
- Track 1 (speech): `Turn { id: 1, speaker_id: Some(1), turn_duration: 48000,
  post_turn_silence: 4800, words: [], splices: [] }` → hash `hA`, present in the snapshot.
- Track 1: a **second** turn `Turn { id: 2, speaker_id: Some(1), turn_duration: 24000,
  post_turn_silence: 0, words: [], splices: [] }` → hash `hB`, inserted by a `type = 0`
  delta `InsertAfter(track 1, After(hA), hB)` recorded *after* the snapshot, so opening the
  fixture exercises `load_and_replay`'s delta application (snapshot + delta), not just the
  snapshot path.

> Keep `words` and `splices` empty: Step 13 pins the *container* formats (turn/label/
> snapshot/delta/metadata) round-tripping through a committed file; the inner word/splice
> bytes are already pinned by Step 4's unit tests, and no command builds real words until
> M4.

**Metadata (`type = -1` at row 3, non-default, canonical order):**

```
Metadata {
    project: ProjectMeta { name: Some("Fixture Project"), aligned_groups: vec![] },
    tracks: vec![TrackMeta {
        id: 1, name: "Host", source_type: File,
        source_path_relative: "audio/host.wav",
        source_path_absolute: "/nonexistent/vocalboard-fixture/host.wav",
        resampled_path: None, codec: "wav",
        source_sample_rate: 48000, source_channels: 1,
        project_start_sample: 0, original_length_samples: 48000,
        cut_length_samples: 0, drift_ppm: 0.0,
        room_tone_hash: None, room_tone_length_samples: None,
        models_used: ModelUse::default(), enhanced_path: None,
        wet_dry_ratio: 0.0, disfluencies_identified: false,
        created_at: "2026-01-01T00:00:00Z", updated_at: "2026-01-01T00:00:00Z",
    }],
    speakers: vec![SpeakerMeta {
        id: 1, name: "Alice", color_hint: Some("#3366cc"),
        embedding_hash: None, track_ids: vec![1],
    }],
}
```

Both source paths are intentionally non-existent, so on open the track resolves to
`FileResolution::Missing` and `open_project` returns `missing_tracks == [1]` (no
`FoundViaAbsolute` write-back fires, so `recovery` stays `None` and nothing is written to
the temp copy).

**Resulting journal (ids are AUTOINCREMENT, in this order):**

| id | type | payload | meaning |
|----|------|---------|---------|
| 1  | 1    | hash of snapshot blob `{0:[hL], 1:[hA]}` | initial snapshot |
| 2  | 0    | `encode_delta_batch([InsertAfter(1, After(hA), hB)])` | append turn B |
| 3  | -1   | hash of metadata blob | the `Kind::Metadata` row (G1 target) |

`store` rows: the snapshot blob, `hL`, `hA`, `hB`, and the metadata blob.

**Expected post-open state:** track 0 = `[hL]`; track 1 = `[hA, hB]`;
`metadata == fixture_spec().metadata`; `sample_rate() == 48000`;
`missing_tracks == [1]`; `recovery == None`.

## Implementation steps

### 13.1 — `fixture_spec()` + the generator (`engine.rs` test module)

In a new section of `core/src/project/engine.rs`'s existing `#[cfg(test)] mod tests`:

1. Define `struct FixtureSpec { sample_rate: u32, label: Label, turn_a: Turn, turn_b: Turn,
   metadata: Metadata }` and `fn fixture_spec() -> FixtureSpec` returning the content above.
2. `#[test] #[ignore] fn gen_fixture()`:
   - Compute the fixture path from `CARGO_MANIFEST_DIR`; `std::fs::remove_file` if present
     (ignore not-found); ensure the `tests/fixtures` dir exists.
   - `Db::create(&path)` (runs migrations → `user_version = 1`, creates the 3 tables).
   - Build a transaction on `db.conn_mut()`:
     - `db_project::insert_project_row(&tx, 48000)`.
     - `store_label(&spec.label) -> (hL, lbytes)`; `store::put(&tx, &hL, &lbytes)`.
     - `store_turn(&spec.turn_a) -> (hA, abytes)`; `store_turn(&spec.turn_b) -> (hB, bbytes)`;
       `store::put` both.
     - Build `PerTrackTrees` (track 0 `Labels` with `[(hL, Arc::new(label))]`, track 1
       `Speech` with `[(hA, Arc::new(turn_a))]`) via `ImplicitTimelineTree::from_sorted_elements`,
       then `snapshot_from_trees(&trees) -> Snapshot`; `store_snapshot(&snap) -> (hS, sbytes)`;
       `store::put(&tx, &hS, &sbytes)`; `journal::append_snapshot(&tx, CommandId::Unknown,
       &hS, 1_700_000_000)`.
     - `encode_delta_batch(&[Delta::insert_after(1, Location::After(hA), hB)]) -> payload`;
       `journal::append_delta_batch(&tx, CommandId::Unknown, &payload, 1_700_000_001)`.
     - `store_metadata(&spec.metadata) -> (hM, mbytes)`; `store::put(&tx, &hM, &mbytes)`;
       `journal::append_metadata(&tx, CommandId::Unknown, &hM, 1_700_000_002)`.
     - `tx.commit()`.
   - **Collapse WAL into the main file** so the committed fixture is one file:
     `db.conn().execute_batch("PRAGMA wal_checkpoint(TRUNCATE); PRAGMA journal_mode = DELETE;")`,
     then `drop(db)`. (`journal_mode = DELETE` removes the `-wal`/`-shm` files; `open_conn`
     flips the temp copy back to WAL on open.)
   - Print the path and the four content hashes via `--nocapture` for the operator to sanity-check.

Use a fixed `applied_at` epoch (e.g. `1_700_000_000`) so the row data is deterministic.

### 13.3 — Inline round-trip test (`engine.rs`)

`#[test] fn g1_fixture_round_trip()`:

- `let bytes = include_bytes!(concat!(env!("CARGO_MANIFEST_DIR"),
  "/tests/fixtures/project_v1.vocalboard"));` write to `tempdir().path().join("p.vocalboard")`.
- `let (ps, outcome) = ProjectState::open_project(&path, &Settings::default()).unwrap();`
- Assert `ps.sample_rate() == 48000`, `outcome.recovery.is_none()`,
  `outcome.missing_tracks == vec![1]`.
- Read `ps.current.trees`:
  - track 0 (`TrackTree::Labels`): `iter()` yields exactly one element with `hash == hL`,
    and `element.text == "Intro"`, `post_label_silence == 24000`.
  - track 1 (`TrackTree::Speech`): `iter()` yields `[hA, hB]` in order, with the decoded
    `Turn` ids `[1, 2]` and durations `[48000, 24000]`.
  - Recompute `hL`/`hA`/`hB` via `store_label`/`store_turn` on `fixture_spec()` and assert
    equality with the loaded tree hashes (this is the content-addressing tripwire).
- Assert `ps.current.metadata == fixture_spec().metadata` (the end-to-end
  `load_metadata` + `load_current_metadata` check — the Step 13 metadata requirement).

## Test plan

| id | test | location | asserts |
|----|------|----------|---------|
| F1 | `gen_fixture` | engine.rs (`#[ignore]`) | writes a single-file fixture; not run in CI |
| F2 | `g1_fixture_round_trip` | engine.rs | sample_rate, trees (`hL`; `[hA,hB]`; decoded ids/durations/text), `metadata == fixture_spec().metadata`, `missing_tracks==[1]`, `recovery==None` |
| F3 | `fixture_v1_opens` (public API) | tests/fixture_roundtrip.rs | open succeeds; sample_rate; `recovery.is_none()`; `missing_tracks==[1]` |

F2 is the authoritative G1 check (deep metadata + tree equality); F3 satisfies the
"fixtures-based round-trip suite in `tests/`" convention via the public surface.

**Why these catch a format break:** if any `v1` postcard schema or the tag byte changes,
the committed blobs either fail to decode (F2/F3 see an `EngineError` instead of `Ok`) or
decode to different structs (F2's `metadata`/tree equality fails, or the recomputed
`hL/hA/hB` no longer match the committed tree hashes). Either way CI goes red — the G1
tripwire — signalling the format-handling work the change owes: for a **blob-format**
change (the likely Phase-1 case, e.g. M2 splices / M4–M5 words), a regenerated fixture +
a `min_app_version` bump per the pre-1.0 `mod v1` policy (no `user_version` migration); for
a **SQLite-schema** change, additionally a numbered `migrations/000N_*.sql` and a
`user_version` bump. See the two-axis note under *Out of scope / deferred*.

## Out of scope / deferred

- No new wire format and no schema migration are introduced in M1 Step 13. Note the two
  *independent* versioning axes (per [data-model.md § Schema version](../design/data-model.md#schema-version)):
  - **`PRAGMA user_version`** (the 3-table SQLite DDL) is expected to stay at `1` through
    all of Phase 1 — M2–M7 add audio/ML/import/editing/packaging, none of which alter the
    `project` / `store` / `journal` tables (timeline + metadata live in *blobs*, not
    columns; recording-track tables are Phase 3). The M6 migration-consent dialog is built
    defensively, but no `migrations/0002_*.sql` is scheduled in Phase 1. So this fixture's
    `user_version = 1` is not expected to be superseded before release.
  - **The blob format-tag nibble** (turn / splice / word / snapshot / metadata postcard
    shapes) *will* change *within* Phase 1 — M2 fills in real `Splice`s, M4/M5 fill in real
    `Word`s. Those are versioned independently of `user_version` via the format-tag byte +
    lazy migration. **All of Phase 1 is pre-1.0** (no released files in the wild), so per
    the pre-1.0 clause in the `mod v1` doc-comments the expected handling is to **revise
    `mod v1` in place** — *not* add a `mod v2` / bump the format-tag nibble / keep a v1
    deserializer. Such a revision must **regenerate this committed G1 fixture** and the
    pinned byte/hash unit tests, and SHOULD bump `min_app_version` (so stale dev/internal
    files made under the old shape are cleanly refused rather than silently mis-decoded) —
    all with **no `user_version` migration**. The `mod v2` + retained-v1-deserializer +
    `From<V2>` machinery is the *post-1.0* path and stays dormant until the v1 shapes
    freeze at first release. So the *next* touch to this fixture is most likely an
    in-Phase-1, in-place v1 blob-format revision (M2/M4/M5), not a Phase-2 SQLite migration
    or a `mod v2`.
- Word/splice-level byte pinning beyond Step 4's unit tests (no command builds real words
  until M4).
- The Missing-Files dialog UI (M6) — the fixture surfaces `missing_tracks == [1]` but no
  UI consumes it yet.
